### Abandoned: Option B for tsconfig paths
**Decision:** Attempted to put all `paths` in root `tsconfig.json` and remove `@/*` from children. Discovered that Payload CLI auto-generates files (e.g., `app/(payload)/layout.tsx`) with `@/payload.config` imports. Changing these files is risky — Payload CLI may regenerate them on `generate:importmap` or `generate:types`. **User decided to postpone this refactor** until the `@/*` pattern is refactored out of auto-generated files.

## Decisions & Rationale
- **Option B (partial extraction) over A (full factory) or C (re-export chain)** for #4: Payload CLI (`generate:types`, `generate:importmap`) is sensitive to `payload.config.ts` location. Keeping a local `buildConfig()` call is safest. Extracting everything *inside* that call is purely mechanical and zero-risk.
- **Keep `astro/tsconfigs/strict` in child tsconfigs, not the base:** The Astro strict config resolves from `node_modules/astro`, which exists at package level (via pnpm symlink), not at the `astro/` folder level.
- **Keep `baseUrl` in child tsconfigs, not the base:** TypeScript resolves `paths` relative to `baseUrl`. If baseUrl lives in the base config, all children resolve paths relative to the base config's directory.
